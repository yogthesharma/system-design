# System Design

Standalone learning repo. Work here on its own — no other repos required.

**Phase (for your own roadmap):** Capstone

## Context

System design is composing caches, queues, databases, and load balancers into something that scales and stays correct enough. Practice common designs and tradeoffs entirely in this repo — other topics help in life, but this folder stands alone as a design gym.

This repository is the single place for everything related to **System Design**: notes, exercises, and small projects. Clone it, open it, and treat it as a complete unit of study.

## Scope

- Scaling reads and writes
- Caching and rate limiting
- Queues and async processing in design diagrams
- Consistency choices
- Classic designs: URL shortener, feed, chat, file store, etc.

## Outcomes

When you are done with this repo, you should be able to:

- Lead a 45-minute design of a common product
- Call out bottlenecks, SPOFs, and consistency tradeoffs
- Produce clear diagrams and capacity back-of-envelope estimates

## How to work in this repo

1. Read / write concept notes under `notes/`.
2. Solve practice problems under `exercises/`.
3. Ship at least one small project under `projects/` that forces the ideas to stick.
4. Tick the checklist below as you go.

You do not need any other curriculum repo open while you work here.
